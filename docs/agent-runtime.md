# Agent桌面后端：显式启用的独立资料模式

本机源码已提供 `workbench.agent_memory.AgentFactory`，直接复用正式 CompanionChat 和已核对的依赖/摘要/撤回候选，运行时不导入合成测试模块，不改写人设函数、不使用空核心资料替身。第一层仍按当前程序只读加载；测试中的人设、基础资料与HTTP替身只存在于测试夹具。

日常默认入口保持原后端。源码启动时，设置 `GERNZE_AGENT_PROFILE` 为新的独立绝对目录，桌面会把该目录交给 AgentFactory，再由既有 WorkbenchHost 启动真实工作台。不要使用原安装资料或旧研究目录。本模式使用独立的 `workbench/agent-chat-sessions.sqlite3`（schema 6），拒绝旧1/4/5版直接接管；旧库不迁移、不复制、不补建样例，关闭该显式入口后仍可使用原入口。凭据复用现有系统存储封装并按资料身份另设命名空间，需在该模式单独配置连接，不自动复制旧密钥。

可选设置 `GERNZE_AGENT_SOURCE_CONFIG` 指向本机范围配置文件。未设置时不发现、读取任何Agent库。只接受如下字段，示例中的值需要由维护者换成明确授权的实际范围；文件不应进入公开源码或发行包：

```json
{
  "format": "gernze-agent-source-v1",
  "path": "D:/explicit-agent-source/agent-memory.sqlite3",
  "sessionId": "明确选择的会话UUID",
  "entries": {"agent:所选来源的64位哈希": "project_progress"}
}
```

每份配置限定一个会话、1至8条明确来源。可用类型为 user_fact_report、project_progress、external_observation、model_self_report、uncategorized；类型是宿主分类，不表示内容已核实。配置变化后须关闭并重新启动，不能在请求过程中悄悄扩大范围。校验原文、引用和哈希只说明记录匹配，不能证明语义真实，也不是用户批准。课程研究取用模式尚不与这个独立库合并；工厂拒绝 research_enabled 混用。

模型仍走现有连接、安全地址校验及禁重定向HTTP。Agent信息在上下文预算允许时整块加入，回答与实际采用依赖同库提交。提交前通过SQLite现有写者槽锁定来源，源侧仅SELECT、最终回滚保留锁；不持锁等待网络，不修改Agent源行。修订/撤回后排除旧回答、传递历史、缓存与相关摘要，显式原文留底仍能查看。此协调需要源库可取得SQLite写者槽，不能称为操作系统只读权限或跨库原子提交；整库回退、备份恢复和文件替换检测未实现。

摘要由当前聊天流程触发，但沿独立 ag_summaries 待核实路径保存和取用，不写普通 lc_summaries/lm_working/lm_approved，也不送入普通用户事实审批。因此该独立模式暂不提供普通聊天摘要自动进入第二层的完整能力；原默认模式保持原流程。电脑配对Publisher现可连接同一份独立Agent资料库，或由可信宿主直接提供同一个store；独立进程不运行ConversationStore/MemoryLayers初始化，不改owner、不恢复进行中请求。手机同步接收源码已接回独立待核实缓存，但不用于聊天或第二层审批。当前安装包尚未重建或替换，此前研究APK仍只代表独立候选验证。

本轮6项定向检查使用临时库、假HTTP与凭据替身，覆盖真实工作台发包、同库依赖、撤回期间作废、缓存拒读、过滤历史/原文重开、摘要自动触发、无来源配置、范围变更和旧库保护。首次检查中的测试断言与连接清理错误已更正，只重跑失败项；没有重复此前整套检查。未打开个人记忆库，未调用真实模型，未构建/替换EXE、更新手机、提交或发布。源码可运行不等于已在日常安装版启用。

## 配对发布与手机缓存接收（源码，2026-10-29）

电脑更新窗口沿用 `GERNZE_AGENT_PROFILE` / `GERNZE_AGENT_SOURCE_CONFIG`；命令行Publisher提供 `--agent-profile` / `--agent-source-config`。配置须与桌面一致，且桌面新版工厂至少启动一次，写入资料身份和来源范围绑定。独立发布进程只连接已存在的schema6库，校验绑定后导出，不启动第二个聊天实例，不复制原文/人设/密钥到手机。未显式配置时新能力关闭，原分层同步、安装包下载与授权管理仍按原入口工作。

新增 `GET /v1/agent-cache/info` 与 `POST /v1/agent-cache/snapshot` 使用原TLS、证书和配对授权表。请求不能传资料路径或改来源范围；快照范围由认证pairingId生成，限制64条/1MiB，完整替换和序号同库保存。导出时重新核对来源；撤回后能发送较新序号的完整空快照，让接收端删除旧缓存。保留已验证候选协议名 `gernze-agent-pending-cache-candidate-v1` 以匹配现有接收验证器，不因此宣告协议稳定或正式发布。

导出适配会写现有库的来源新鲜度元数据和传输序号，不写聊天/原文/人设/审批内容；“readOnly”指手机没有回写与审批接口，并非该导出进程只有文件只读权限。导出沿授权锁→源SQLite保留锁→桌面事务的既有顺序，不持源锁等模型网络。已发送内容无法靠事后撤销追回，整库恢复的序号连续性仍未实现。

手机同步源码在普通分层同步成功或失败后都可独立尝试接回缓存，每轮最多一次；两条通道分别报告结果。Agent失败保留缓存且不回退普通同步结果；离开面板释放监听和缓存连接。新原生方法沿原SecurePairStore/PinnedHttp/Job，网页不拿到URL、Bearer或配对秘密。独立缓存不会自动出现在聊天上下文，也未接入第二层审批。缓存离线时只能代表最后一次接收状态，不能证明源目前有效。

4项新增定向场景使用实际本机TLS与临时资料通过，含真正的独立Python进程在聊天进行中导出、owner/待处理状态保持、原请求正常完成、认证/跨配对范围/撤权、撤回完整空快照、不同来源绑定拒绝、原发行接口仍可用。手机7份源码经差异核对接回，原生Java与此前已编译候选逐字节一致；当前真实入口只做1次内存打包检查，新模块与两原生方法进入bundle。未重复旧浏览器/Android套件，未重建本轮APK、安装手机、替换现用服务或调用真实模型；Android原生实跑与真机仍待验证。
