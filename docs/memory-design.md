# 莉宝三层记忆：已定权限与现成项目核对

更新：2026-10-18。状态：手机分层代码已接入既有摘要与审查入口，合成浏览器检查通过；新安装包与真机效果另行核验。电脑版及新分层的双端同步尚未接入，旧主动笔记同步继续保留。

## 用户已确定的边界

| 层级 | 内容 | 写入权 | 回答时如何使用 |
|---|---|---|---|
| 第一层：核心设定 | 用户确认的角色设定、固定相处原则及基础资料 | 只有用户决定；AI维护者也须有用户明确授权。聊天模型没有任何写入口 | 每次回答前，由程序加载当前有效、完整的精简核心；不能因检索没命中而省略 |
| 第二层：已审核记忆 | 用户或其明确委派的审查AI审核通过的长期记忆 | 仅独立授权的审查入口可写；日常聊天模型不能修改、删除或升降级 | 回答器按话题读取；重要已确认约定可常驻，普通条目按需带入 |
| 第三层：压缩工作记忆 | 从第四层原文压缩出的摘要与必要原话索引 | 既有摘要调用经程序校验来源后只写此区；不另做逐句提取 | 作为未审核资料参与相关回答，不能覆盖前两层 |
| 第四层：聊天原文 | 原始用户与助手消息及时间 | 聊天保存链路追加会话；与压缩结果分库存放 | 是追溯资料，不是已审核事实；压缩不删除原文 |

第一层＞第二层＞第三层是应用组织资料和处理冲突的规则，不是模型内部的数字权重。每次送入第一层不等于能保证任何模型百分之百遵守；必须同时限制写入口，不能只靠提示词。不得在删除旧上下文、摘要或自动整理时顺手重写第一层。

审查间隔由用户指定，不固定为每7天；此前“一周”只是讨论示例，不自动创建定时任务。由用户本人或其明确指派的审查AI集中审查第三层新增和修改，支持整批通过、单项纠正和排除。当前主干被授权承担审查，用户随后自行创建专门审查分支。授权审查者批准具体版本后，可经独立审查入口写入第二层，无须把已经委派的普通审查逐条重复交用户确认。时间经过、没有回复、没有纠正，都不构成批准；审查后又被聊天模型改过的版本不能沿用旧批准。

摘要器和外部制作任务只接触第三层的必要资料或合成示例，不获得第一、第二层文件、写入凭据和管理接口。回答器可以得到前两层所需文本，但不能因此获得其存储写入权。不同用途调用要分开能力，不把管理员权限交给同一个通用接口。

用户当前明确纠正可以用于当次交流，并生成第三层待审核变更；不能因第一、第二层只读而否认用户这次说的话，也不能将这次纠正自动写回上层。


## 审查分支职责（用户将自行创建）

审查分支负责核对第三层候选的原文来源、用户/助手/引文身份、明确纠正、计划与已发生、日期、重复和互相冲突。输出通过/纠正/排除/待确认及对应理由、来源和具体修订号；经其授权范围内的独立审查入口提交第二层。当前接口尚未实现时只交审查结果，不直接覆盖数据库，不假称已晋级。

审查者不能修改第一层；冲突涉及核心设定时交用户决定。审查只取必要的候选、来源及最小冲突对照，不默认开放完整人设或私人资料给其他制作任务。主干负责存储、权限、压缩、上下文和同步接线，分支不重复开发这些模块。尚无真实第三层数据时，只核对规则，不编造已审记录。摘要和原话索引不足以核验的断言标为待确认，不把模型摘要本身当证据。审查间隔与摘要间隔、双端同步间隔是三项不同设置，互不自动改动。

## 选型建议与落地范围

建议采用AIRI的受限写入接口组织方式，结合只读核心块概念，复用莉宝已有会话保存、纠正失效、SQLite/IndexedDB和配对传输。暂不安装另一整套桌宠、Agent服务或向量数据库。AIRI依赖Vue/Pinia，莉宝当前是原生JS/Capacitor/Python，不能把单文件原样放进来就算接好；如后续复制可复用代码，先固定版本并保留MIT声明。

建议在同一个记忆模块内分独立存储区：核心配置、审核库、工作库。第一、第二层不放在模型写接口可打开的库里。回答时由可信程序只读组装；工作记忆接口只接收条目和版本，不接受任意路径、库名、层级或SQL。审核是独立的用户/授权审查者操作，带具体版本和审查身份凭据；这一凭据和能力不提供给日常聊天或记忆提取模型。审查AI的委派不是给所有API开放第二层写权限。物理分文件只是组织方式，权限仍须由入口和持有的能力保证。

## 当前手机接线与限制

- 原文仍在 `chat-journal` 会话库；已有 `summary-policy` 按摘要间隔运行，默认7天、最短1天。一次只压缩一段较早的完整轮次，最近6轮保留原文；不是到期一次扫完全部历史，也不在后台自行唤醒。
- 压缩成功且原文范围校验一致后，摘要接入独立第三层库。重复接收相同摘要不重复新增；接收失败可从已保存摘要恢复，不再次付费调用模型。
- 回答由宿主组装只读核心、第二层和第三层；摘要调用只接收原文块与旧摘要，不提供第一、第二层资料或审查能力。聊天JSON中自行夹带 `memory`、层级或批准字段不产生写入。
- 核心每轮必带。第二、三层按关联和近期选择，在预算不足时先移除完整的第三层条目，再移除可选第二层条目，不切碎第一层。语义相矛盾但编号不同仍需审查；不能声称程序能自动理解所有事实冲突。
- 第二层、第三层分别存于独立IndexedDB。审查UI持有独立能力，聊天输送器没有晋级、删除第二层或修改核心的接口。目录/数据库隔离本身不等于操作系统安全沙箱。
- 审查导入绑定具体候选修订号，候选变化须重新审核。审查间隔独立设置，留空为按需；到期仅显示待审状态，不自动批准。原文从对话与记忆书架查看。
- 个人安装包可由本机已确认基础库生成只读核心；公开源码只含生成器，干净构建没有个人资料。完整私人角色设定、基础SQLite、生成JSON和真实审查结果都不加入源码白名单。
- **现有双端同步只覆盖旧主动笔记**，不等于新第二、第三层互通。后续须分别保留层级、版本和批准来源；新增、修改、删除及并发冲突沿用现有因果版本合并思路，不能直接拼数组、按最后时间覆盖或让第三层导入第二层。第一层仅走用户授权的配置更新；第四层原文暂不自动互传。

本轮方法研究仅参考外部实现，没有复制代码或新增第三方记忆依赖。合成检查不替代真实模型语义、手机存储与双端同步验收。

## 实际保存状态（1.0.17）

模型回答不是数据库查询结果。设置中的“刷新保存状态”直接读取L1/L2/L3和第四层会话库；第四层有真实轮次、保存时间及只读原文节选，第三层有压缩间隔和当前未运行原因。回答上下文带宿主只读计数，但模型仍可能误述；核验以本机状态界面为准。只有程序知道所选上下文之外还保存多少原文，未提供某段内容不能称该库不存在。临时合成测试数据不会注入个人库。
