## 分类与审查的关系

聊天压缩后通过独立审查的第二层仍由现有记忆服务管理。研究目录另存见闻、兴趣和课程三个主题，可并存主题；来源、主题、信任、用途限制分别记录。外部资料、Agent 推断和未审用户陈述不会因分类标签成为已审第二层。本接口没有批准第二层的能力，未放宽现行独立审查准入范围。

## 存储与版本

`workbench.research_catalog.ResearchCatalog` 使用现有 Python 标准库 SQLite。构造只保存显式绝对路径；宿主显式调用 `initialize()` 才建表或升级研究目录。目录仅查询具名元数据列；正文、来源原文分别放入 `rc_bodies`、`rc_source_payloads`，不会为了列目录预读标题、片段或正文。

来源和条目均使用 UUID 身份与不透明修订，事务内核对预期版本；不同修订不按大小比较。原始来源文本按版本保存，普通请求核对其元数据/hash，不加载原文归档。派生条目继承精确父版本及全部课程范围；任一祖先变化、撤回或冲突，旧派生物不能继续取用。同一未解决冲突组的后续成员也被隔离。共享祖先在一次事务内复用元数据校验结果，避免菱形依赖指数展开。

研究目录结构为 `rc_meta schema=2`。从早期研究目录 v1 显式升级时不编造缺失的来源原文，也不把这些旧研究根来源当作可验证新来源；既有第一/二层不批量重新分类或停用。

## 实际桌面请求接线

`create_desktop_chat(..., research_enabled=True)` 才创建 `ResearchJournal` 与 `ResearchProvider`，默认 `False` 不导入或初始化这条研究路径。`ResearchJournal` 让回答和本轮实际暴露的来源依赖保存在同一个会话 SQLite 事务，提交前再次核对来源和请求范围；远端模型等待期间不持有数据库写事务。取消、禁用或来源变化会使旧生成结果作废，不能留下已完成回答而没有依赖记录。

选择由可信 Python 宿主绑定到单次 request/session。`ResearchAccess()` 默认为普通用途；课程用途还必须匹配具名课程范围。网页正文、模型字段、请求中的 `study=true` 或固定追问次数都不能签发学习权限。有限中文拒读规则只能缩小已有范围；当前用户亲自提供的材料仍留在本轮输入。课程单次用途入口已按下节接回源码，默认宿主仍未启用；只在书架查看不签发聊天权限。

整批身份、版本、用途和预算在正文查询前校验。研究材料只填补已有上下文预算，不挤掉本轮输入或已选近期整轮；不足时整块省略。目前预算前置只支持现有 UTF-8 保守估算，其他计数器需要显式适配。研究资料作为低信任材料发送，不能授权工具、改写角色设定或审批记忆。

历史和重放先核对元数据再查询聊天正文。权限不足的课程轮不加载；有研究依赖的旧回答需来源仍有效，缓存重放还需同一宿主取用范围。实际进入请求的历史依赖会继续传给新回答，不能通过多聊一轮去掉来源限制。新进程没有重新绑定范围时也不能直接重放课程缓存。

## 摘要与旧版本边界

新研究会话库标为 `user_version=4`，旧默认 `ConversationStore` 及旧研究v2/v3运行时拒绝该库，避免旧路径不校验依赖就重放。此升级仅在显式启用的研究会话发生，不是自动升级作者现用库；回退安装版前须恢复未启用的独立库/备份，不能只调小版本号。

研究相关轮次目前从旧摘要读取路径中排除，并在旧摘要提交入口再次拒绝；原文保留。筛选发生在组成摘要批次之前，可整理数量也只计算普通候选，不会因最早几轮研究记录暂缓而堵住后续普通聊天，也不把研究轮误标为已整理。研究专用受限摘要已按下节接回；研究专用核对与只读传输已按文末接回，研究轮仍不进入旧用户事实L3/L2。旧库没有来源记录的历史和既有已审第二层沿用旧语义，不据此宣称全部旧数据已经满足课程零读。

## 最小宿主用法

仅在隔离资料库中验证；`course_id` 必须来自可信宿主课程目录，不能从模型输出接受。

```python
from workbench.encounter_composition import create_desktop_chat
from workbench.research_catalog import ResearchAccess

chat = create_desktop_chat(absolute_settings_path, research_enabled=True)
catalog = chat.research_provider.catalog
source = catalog.create_source('course', supplied_source_text, courses=(course_id,))
entry = catalog.add_entry(supplied_research_text, [source], facets=('course', 'interest'))
metadata = catalog.catalog()  # Metadata only; no body SELECT.
chat.research_provider.bind(request_id, chat.store.session_id, [entry],
    access=ResearchAccess('study', (course_id,)))
reply = chat.reply_request(current_user_text, request_id=request_id)
```

不能把示例中的宿主绑定直接暴露为不受控 HTTP 参数。研究条目和课程映射的写入者也必须可信；仅凭元数据无法识别被整体伪造为普通资料的课程正文。

## 显式资料导入

`research_import.ResearchImporter(path).apply(packet, category='encounter')`为可信宿主Python接口，尚未在服务器、模型或界面开放写入。`load_packet(path)`只读明确指定的单个UTF-8 JSON，不扫描文件夹，不跟随包内路径或执行源码。协议`gernze-research-import-v1`严格限制字段、条数及UTF-8大小，拒绝重复JSON键。包包含namespace和items；单项id/revision/previous/title/body/source_text/source_ref/review_status/review_scope缺一不可。首次previous为null，修订须精确匹配当前外部修订；修订号不排序。

category、courses和source_kind由宿主传入，不从正文推断。course须有明确课程UUID范围，其他分类不得夹带课程；条目既有范围不能通过再次导入改变。全部资料保持未获L2批准的信任状态；`reported_reviewed/reported_verified/partial/unverified`是交付方记录，独立于truth/trust与学习许可。表`rc_import_items`只存目录元数据和当前修订映射，`rc_import_receipts`保留历史修订摘要；来源payload完整保存单项原始文本及验收记录，当前展示正文包含来源、验收范围和第一人称归属提示。两表使用独立import_schema1，现有research schema2不变。

整个批次含首次研究表创建均在同一BEGIN IMMEDIATE事务内，失败回滚；不构造ConversationStore、不抢占聊天owner、不改变lc库版本或批准表。同修订内容不同、旧修订重放、错误前驱、来源独立改变/撤回/冲突均拒绝；更新时保留旧来源原文并让旧来源依赖失效。新增版本不会静默复活其他旧派生条目。目录标题/状态只按精确entry修订读取，点击正文仍经原访问检查。

## 单次课程对话

宿主构造参数`WorkbenchServer(..., research_enabled=False)`保持默认关闭；显式True才构造研究Journal/Provider并升级该独立库，不能直接对现用库试开。`StudyChat`可在默认宿主创建，但status只检查运行状态，reply关闭时拒绝，不建研究表。`chat.study.status {}`与`chat.study.reply {text,request_id,materials:[{id,revision}]}`沿用本机Host/Origin/Bearer保护和严格字段白名单。只有人物场景声明课程调用；设置仍只有原三项研究只读命令。模型工具未开放此入口。

服务先核对材料分类、精确修订、来源状态与整批范围，再从可信元数据解析课程UUID，不从HTTP接受scene/courses/trust/grant。`host_selection`只绑定当前执行上下文的确切文本/request/session，finally重置；来源/body读取仍由ResearchProvider预算前置控制。接口请求不留下可被普通chat.reply继承的全局binding，不发行可带往其他请求的课程票据。普通旧request缓存重放拒绝；同一显式选用重试可在来源及用途不变时返回有效缓存，并带research_use状态。

界面从课程分组明确“用于下一次提问”，不读取正文或发送模型；移除后下一问走普通接口。选择发送一次即消耗，失败不自动保留重试；关闭对话或卸载清理。当前课程回答直接显示，普通history在元数据分页前排除非空研究依赖，避免开聊天窗口重新读取课程回答；原文仍在显式日期书架。后续普通模型上下文继续按依赖/用途门槛过滤。此段为阶段5基线；带依赖摘要及手机只读同步已按后文接回，旧库无标签历史和手机课程研究聊天仍未完成；普通摘要单次取用见阶段8，不得扩大为全应用所有旧资料零读保证。

## 受限研究摘要

`research_summaries.py`复用既有SummaryAdapter和ContextManager有限worker；Journal显式创建summary_schema2以及rc_summary_meta/bodies/coverage/attempt、rc_turn_summary_links。research schema仍为2，显式研究会话的user_version为4，旧v2/v3研究运行时不得降版本回退。默认research_enabled=False的普通会话仍为原版本且不创建研究表。

普通摘要路径优先，结果not_due才选择有权限、到期且满足最小批次的研究分组，一次请求最多一个worker。分组由实际来源manifest的用途/课程集合决定；普通请求SQL先粗排课程，随后逐项核对元数据，正文最后读取。扫描最多512项旧轮次；摘要目录检查最多64条元数据并保留16条，当前请求最多采用4条研究摘要。这些是局部资源边界，不是全历史无损保证。

模型只总结本次new_block，不接收旧研究摘要背景；输出协议仍只有text与经本地适配核对的来源轮次。若原文回答实际依赖旧摘要，宿主保存精确父引用并展平外部来源及最多256项原文状态、最多64项摘要引用。提交时复核当前原文内容哈希、来源、权限、epoch、owner和未整理状态。正文/元数据/覆盖同事务；实际回答的来源与摘要引用也同事务。读取时核对元数据状态和版本，摘要正文单独校验hash/字节。合法原文更正/撤回经过既有barrier，直接篡改整库不是受保护的外部输入模型。

ContextManager只在现有预算有余量时整块读取研究摘要；本次明确选中的材料优先，未知计数器不读摘要正文。ResearchProvider继承实际采用摘要及实际带入旧轮次的依赖，并在最终提交前复核；来源/原文/父版本失效使旧摘要及相关缓存不能回流。普通零课程结论适用于这条具名研究路径，旧库无来源记录数据不在保证中。

这些摘要保持未确认研究资料身份，不批准L2，不写旧lc_summaries/lm_working，不误标lc_turns.covered，也不进入旧LayerSync。旧原文与研究元数据保留；研究专用核对和手机只读缓存见下节；手机课程用途/研究上行及Agent兼容仍需另接。29项新增检查及30/21/3/14项相关回归通过，仅临时合成库和假模型，无实际库迁移、真实API、构建安装或发布。

## 独立研究核对与手机只读传输

`research_review.py`在现有DesktopMemoryReview的同一排期/单次调用门内核对普通用途研究摘要，与旧待审交替，课程正文不自动读。模型只见具名摘要及其所附聊天/研究输入，不见L1/L2，也不获工具或权限。输出限定supported/defer/reject及具名证据编号，结果保存在rc_summary_reviews；supported的含义仅为与输入相符，仍为研究资料。写入前复核来源、原文、owner、epoch、开关及新增聊天水位，记录/完成日志同事务；reject在摘要、全部父引用、后续回答提交和缓存重放前生效。

只有显式研究会话使用user_version4/summary_schema2；v3显式升级保留原数据并新增独立核对表，旧运行时必须拒绝而非降版本。普通默认库不迁移。原先三条outside_auto_admission_scope仍是旧用户事实审查准入待办，与本功能无关。
